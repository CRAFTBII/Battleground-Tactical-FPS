# 地图专属玩法规格 · v1.2（mechanics.md）

> 项目：战地突击 Battleground Tactical FPS（Three.js r160）
> 作者：文策渊（design-strategist） · 版本：v1.2「地图特色化」
> 状态：**设计定稿**，数值待 [PLAYTEST] 微调
> 范围：port / desert / suburb 三图各 1 个独占玩法；数据已写入 `js/maps/*.js` 的 `mechanics` 字段
> 契约：字段结构 = 下方 schema（**与工程侧对齐，结构勿改，数值可调**）；实现由工程侧 `mechanics.js` 承接

---

## 0. 设计原则（三图玩法共性）

1. **每图一个独占玩法**：三图各自只挂一套专属机制，互不混用 → 地图辨识度 = 玩法辨识度。
2. **机制必须与据点玩法共存**：玩法是"在占点节奏之上叠加的节拍器/变量"，不替代 A/B/C 占领、不改变胜利条件（时间到比分高者胜）。
3. **数值节拍自洽**：所有机制按"秒"计时，与局时 600s、据点产分 2s/tick 对齐；不做无限叠加（伤害/回血都设上限与冷却）。
4. **反制对称**：每个机制都有"主动使用方"与"反制方"，避免单向无脑收益（断电可抢修、水塔可反抢、炮击可跑位、空投可蹲守）。
5. **[PLAYTEST] 标注**：凡需实测平衡的数值（伤害/时长/范围/冷却）统一标注，工程联调后按测试反馈收敛。

## 1. schema 契约（与工程侧对齐）

```js
// 每图 mapDef 新增顶层字段：
mechanics: {
  /* ---------- port：探照灯 + 断电 ---------- */
  port: {
    type: 'searchlight',
    lights: [{ x, z, yawDeg, tiltDeg, range, sweepDeg, speed }], // 探照灯参数（见 §2.1）
    powerPanels: [{ x, z }],                                      // E 交互断电（见 §2.2）
    expose: { minimapPing: true }                                 // 被扫到 → 曝露标记
  },
  /* ---------- desert：沙暴 + 水塔 ---------- */
  desert: {
    type: 'sandstorm',
    cycle: { stormSec, calmSec },                                 // 周期：风暴 30s / 平静 90s
    fog: { storm: { near, far }, calm: { near, far } },           // 雾插值（风暴浓/平静恢复）
    exposeDmg,                                                    // 风暴中暴露每秒伤害
    tower: { x, z, r, healPerSec }                                // 水塔占领回血（设施位=建筑 D13）
  },
  /* ---------- suburb：空投 + 炮击 ---------- */
  suburb: {
    type: 'airdrop',
    intervalSec, drops: [{ x, z }],                               // 空投周期 / 候选投放点
    crate: { heal, ammoPct },                                     // 补给箱内容
    arty: { intervalSec, zone: { x, z, r }, warnSec, dmg, radius } // 炮击周期 / 落区 / 警示 / 伤害 / 半径
  }
}
```

> 结构语义：`lights[].x/z` 与 `tower`/`drops`/`zone` 均为**世界坐标中心**（与据点/掩体语义一致）；`yawDeg` 为水平朝向（度，0=+Z 轴，逆时针为正，见 §2.1 角约定）。所有数值单位为米/秒/度，伤害与回血按 HP 计（玩家 100HP）。

## 2. Port「夜港工业区」—— 探照灯 + 断电

### 2.0 一句话
巡逻探照灯光锥扫描全场，被扫到就曝露；两队抢配电箱断电——断电换夜战优势，但对方可以抢修点灯反制。

### 2.1 探照灯（lights）

**数据（已写入 port.js）**：

| 灯 | 架设位置（制高点） | x, z | yawDeg | tiltDeg | range | sweepDeg | speed |
|----|------------------|------|--------|---------|-------|----------|-------|
| L1 | 主库屋顶（B1） | 160, 112 | -59 | -12 | 45m | 35° | 25°/s |
| L2 | 西泵房屋顶（B7） | 100, 74 | -50 | -15 | 40m | 30° | 30°/s |
| L3 | 东泵房屋顶（B8） | 160, 186 | 130 | -15 | 40m | 30° | 30°/s |
| L4 | 控制楼顶（B2） | 100, 150 | 124 | -10 | 55m | 45° | 20°/s |

**规则**：
- 每盏灯以 `yawDeg` 为中心，在 `[yaw - sweep, yaw + sweep]` 范围内**往复摆动**（角速度 `speed`）。
- 光锥为扇形：`range` 为有效长度、水平角宽 ≈ `sweep*2`、`tiltDeg` 为向下俯角（照地面）。
- 玩家/单位进入光锥且与灯连线未被建筑碰撞体遮挡 → **被照亮（exposed）**。

**曝露（expose）效果**（`expose.minimapPing: true`）：
- 小地图出现**红点标记**（持续显示直到离开光锥后 3s）；
- 玩家被照到时 HUD 出现"⚠ 已曝露"警示 + 3D 轮廓描边（供队友/敌人可见）；
- AI 被照到时小地图也标红点（红队 AI 被照 = 蓝队集火信号）。

**时序**：单灯扫过某点的时间 = `sweep*2 / speed`：L1≈2.8s、L2/L3≈2.0s、L4≈4.5s。全图"每 4.5s 内至少一盏灯扫过主街/据点走廊"——夜港核心张力：**过街必被照，被照必曝露**。

**角约定（给工程）**：`yawDeg=0` 朝向 +Z 轴；正方向为从 +Z 看向 +X 的逆时针（Three.js 右手系，`rotation.y = yawDeg * PI/180`）。L1 的 -59° 即指向 A 中庭方向（从主库顶望向 130,130）。

### 2.2 配电箱（powerPanels）—— 断电/抢修博弈

**数据（已写入 port.js）**：

| 配电箱 | 位置 | 归属倾向 |
|--------|------|---------|
| 蓝侧 | 66, 88（B 点西北） | 蓝方主控（蓝出生区→B 顺路） |
| 红侧 | 194, 158（C 点东南） | 红方主控（红出生区→C 顺路） |

**规则**：
1. **断电**：玩家在配电箱 2m 内按 **E** → 全图 4 盏灯熄灭，进入 **断电期 30s**；断电方获得夜战优势（详见 §2.3 代价）。
2. **抢修**：任意一方（含断电方）在断电期内到**任一**配电箱按 E → 立即恢复供电，探照灯重新开始扫描；抢修者所属队进入 **抢修冷却 45s**（此期间该队不能再按 E）。
3. **断电冷却**：断电动作也有冷却 45s（以"队"计）→ 防止同一队反复开关灯刷优势。
4. **规则优先级（明确无冲突）**：**队冷却 > 抢修权限**。任一队处于 45s 队冷却（断电冷却或抢修冷却）期间，该队**既不可断电、也不可抢修**（电源操作全部阻断）。冷却只按"队"判定，两队冷却互相独立——A 队断电后进入冷却，B 队仍可立即抢修点灯。> 已由质量复验（quality-lead）确认：工程实现取「队冷却期内阻断该队一切电源操作（含抢修）」，符合"防反复开关灯刷优势"设计意图。

**设计意图（断电的代价由"被反制"承担）**：
- 断电不是单向增益。全灯熄灭后，**双方**视野都下降（灯柱灭 = 环境更暗、小地图道路层不变但 3D 可视度降），夜战对双方均有利弊；
- 断电方的真实收益：**自己不再被探照灯曝露**（进攻/绕后窗口）；代价：**对方 30s 内可抢修点灯**——抢修方获得"你们黑灯 = 我们趁机推进"的节奏优势；
- 因此断电是**风险换窗口**：断电要选在"对方主力不在配电箱附近"的时机，否则刚断就被点回来。

### 2.3 断电期的环境表现（给美术/工程）
- 灯柱发光强度 0 → 微光（保留夜港剪影辨识度）；
- 主光（sun/moon）与环境光强度下降至 ~55%，雾 near/far 不变（避免视觉断层）；
- 断电期全图统一，不区分阵营（双方都黑）。

### 2.4 UI / 交互键汇总
| 交互 | 键 | UI 反馈 |
|------|----|---------|
| 断电 | E（配电箱 2m 内） | 交互提示"按 E 断电"；成功后 banner"全港断电 30s" |
| 抢修 | E（任一配电箱 2m 内） | 交互提示"按 E 抢修供电"；成功后 banner"供电恢复" |
| 被照亮 | 自动 | 小地图红点 + HUD"⚠ 已曝露" + 轮廓描边 |
| 断电倒计时 | 自动 | HUD 顶部"断电剩余 24s"（全局可见，双方都看到） |

### 2.5 与据点玩法的关系
- L1/L4 扫描范围覆盖 A 中庭与主街交叉 → **占 A / 过主街 = 高频曝露风险**，逼玩家在"冲点"与"等灯转走"间决策；
- 断电期是**进攻 A/B/C 的黄金窗口**（灯全灭 → 不会被曝露）→ 断电与占点强绑定，制造"抢配电箱 → 断电 → 全员冲点"的战术剧本；
- 反制剧本：防守方看到断电 → 抢修 → 点灯瞬间曝露正在冲点的进攻方 → 防守反击。**一断一修 = 攻防易手**。

### 2.6 联机最小集成建议
- 灯状态为**房主权威**：房主按 `updateMechanics(dt)` 推 `{ k:'searchlight', phase:'on'|'off', t }`，客户端本地渲染光锥/黑暗即可；
- 曝露标记**本地判定 + 广播**：`Net.broadcastEvent({k:'expose', id})` 让队友小地图同步红点；
- 断电/抢修同样房主裁决，广播 `{k:'power', state:'off'|'on', team}`；非房主按 E 只发请求。

## 3. Desert「荒漠前哨」—— 沙暴 + 水塔

### 3.0 一句话
周期沙暴吞噬视野、灼伤暴露者，逼所有人躲进掩体；水塔是风暴中的"绿洲"——占领它，风暴里也能回血。

### 3.1 沙暴（sandstorm）

**数据（已写入 desert.js）**：
- `cycle: { stormSec: 30, calmSec: 90 }` → 周期 120s，其中 30s 风暴 / 90s 平静（**风暴占 25%，节奏合理，不会把"慢节奏"图拖成"全程挨打"**）
- `fog.storm: { near: 15, far: 70 }`，`fog.calm: { near: 120, far: 430 }`（= env.fog 现值）
- `exposeDmg: 4`（HP/s）

**规则**：
1. **风暴期**：雾从 calm 插值到 storm（建议 2~3s 过渡），视野骤降到 15~70m（接近夜港近雾水平）；
2. **AI 命中骤降**：风暴期内 AI（红蓝都算）对**20m 外**目标命中率 ×0.5（实现见联机建议；本地 AI 同理）；
3. **暴露伤害**：风暴期内，**未处于任何建筑内/掩体后/水塔圈内**的单位每秒受 `exposeDmg=4` 伤害。判定：单位 8m 内无 `cover` 或建筑碰撞体且不在水塔圈 → 视为暴露；
4. **平静期**：雾恢复、AI 命中恢复、暴露伤害停止。

**时序**：开局 `calmSec=90` → 90s 后首次风暴 30s → 平静 90s → …… 首爆在第 90s（与首个占点节奏吻合，玩家有充足时间理解机制）。

**平衡核算**：风暴 30s 全程暴露 = 120 伤害 → **致死但需全程站空地**。实际玩家会找掩体/水塔，受伤通常 0~60。压迫感足够但不至于无解。

### 3.2 水塔（tower）—— 可占领回血设施

**数据（已写入 desert.js）**：
- 建筑设施位：D13 tower，坐标 `x:150, z:130`（角点，w4 d4 h8）
- `tower: { x: 152, z: 132, r: 10, healPerSec: 5 }`（回血圈中心 = 塔心，半径 10m）

**规则**：
1. **占领**：与据点同款"圈内人数多者推进度"逻辑（复用 `Game.updateCaps` 模式，单独 1 个点，进度 100 需约 12s 单人在圈）；占领方 = 圈内蓝/红人数多者；
2. **回血**：占领方存活单位在水塔圈 r=10 内 **每秒 +5 HP**（上限 100）；敌方在圈内 **不享受回血**，且可反抢（人数压制即易主）；
3. **回血与据点并存**：水塔不属于 A/B/C 三据点，不产分；它是"持续战斗续航"资源点。

**位置 rationale**：水塔位于主道东侧、A 中庭与 B 点之间偏南（152,132），距 A(170,170) ≈ 40m、距 B(96,118) ≈ 58m——**夹在蓝方推进线与 A 点之间**，是"占 A 前先占塔回血"或"守塔反打"的支点。

### 3.3 UI / 交互汇总
| 事件 | 反馈 |
|------|------|
| 风暴开始 | banner"沙暴来袭 30s — 找掩体！" + 屏幕边缘沙尘粒子 |
| 风暴结束 | banner"沙暴平息" + 雾渐退 |
| 暴露受伤 | 每 0.5s 轻红闪 + HUD"沙暴灼伤" |
| 进入水塔圈（已占领） | HUD"水塔回血中 +5/s" |
| 水塔易主 | banner"水塔被蓝/红方占领" |

### 3.4 与据点玩法的关系
- 沙暴是**节奏压缩器**：风暴期远距交战不可行 → 被迫转入建筑/水塔附近的近身接触战，与荒漠"长视线慢节奏"形成反差高潮；
- 水塔是**续航引擎**：占点损耗后先去水塔回血再回点 → 让 B/A 之间的推进线多一个战术目标；
- 反制剧本：A 点被围 → 守方退水塔回血 → 攻方必须分人压塔，否则被耗死。**塔不是附属，是第三战场**。

### 3.5 联机最小集成建议
- 沙暴阶段**房主权威**：`{k:'storm', phase:'storm'|'calm', t}` 广播，客户端插值雾 + 本地伤害判定；
- 暴露伤害本地可判定（colliders + 水塔圈是共享数据），但**伤害结算走房主**（复用 `applyDamage`，owner=null 表示环境）；
- AI 命中惩罚：房主侧对 AI 射击做 `if (storm && dist>20) hitChance*=0.5`；
- 水塔占领复用据点广播 `{k:'cap', id:'tower', owner}`（新增 id 不与 A/B/C 冲突）。

## 4. Suburb「城郊战场」—— 空投 + 炮击

### 4.0 一句话
运输机周期投下补给箱，两队抢箱；中央广场周期挨炮击——占 A 之前先算好炮击窗口。

### 4.1 空投（airdrop）

**数据（已写入 suburb.js）**：
- `intervalSec: 60`（每 60s 一次空投）
- `drops: [{x:120,z:180}, {x:185,z:110}]`（**每次随机选 1 个点**投放，候选点都在广场外空地，不压 A/B/C 据点圈）
- `crate: { heal: 50, ammoPct: 0.3 }`（拾取：+50 HP，+30% 当前武器备弹）

**规则**：
1. **信标警示**：投放前 5s，目标点出现**绿色信标光束 + 小地图绿点**（"空投即将降落"）；
2. **落箱**：信标结束后补给箱落地（实体，可被碰撞，类似掩体但可拾取）；
3. **拾取**：玩家走到箱旁 1.5m 按 **E** → 立即回血/补弹药，箱子消失；
4. **归属**：先到先得，无阵营锁定（红蓝都能拾取）。

**平衡核算**：空投 60s 一次、每箱价值 = 半条命 + 三成弹药 → **值得抢但不至于颠覆**；信标 5s 的可见性保证两队都有反应时间，形成"抢箱遭遇战"。

### 4.2 炮击（arty）—— 中央广场周期压制

**数据（已写入 suburb.js）**：
- `arty.intervalSec: 45`（每 45s 一轮）
- `zone: { x:150, z:150, r:28 }`（覆盖中央广场 + 干道交叉，A 点(150,150) 在区内）
- `warnSec: 4`（落弹前红色警示圈 4s）
- `dmg: 60`、`radius: 8`（单发伤害 60、爆炸半径 8m）

**规则**：
1. **警示**：每 45s，zone 内出现**红色警示圈**（半径 = 爆炸半径 8m，位置在 zone 内**随机**），持续 4s；
2. **落弹**：警示结束，警示圈位置落 1 发炮弹：半径 8m 内伤害 60（线性衰减，中心 60 / 边缘 0）；可被掩体遮挡（复用弹道判定）；
3. **周而复始**：下一轮 45s 后重新随机落点。

**平衡核算**：
- 伤害 60/发：**不致死但重伤**（100HP → 40HP），两发才死 → 惩罚"站桩占 A"，但不会一轮清空据点；
- 警示 4s：步行 4.4m/s → 4s 可跑 17.6m > 半径 8m → **反应得及就能躲**（不躲 = 惩罚）；
- 每 45s 一次 × 600s = 全图约 13 轮炮击 → 高频但可预判，制造"炮击窗口期"战术节拍。

### 4.3 UI / 交互汇总
| 事件 | 反馈 |
|------|------|
| 空投信标 | 绿光束 + 小地图绿点 + banner"空投 5s 后落地" |
| 补给箱落地 | 小地图绿点保持，直到被拾取 |
| 拾取补给箱 | banner"补给 +50HP / +30% 弹药" |
| 炮击警示 | 红圈 + 屏幕边缘红光 + 音效 |
| 炮击落弹 | 爆炸特效 + 伤害（如命中） |

### 4.4 与据点玩法的关系
- **空投 = 额外争夺点**：60s 一次的箱子让"占点—守点"之外多一个临时目标，双方会分兵抢箱，间接打乱占点节奏；
- **炮击 = A 点节拍器**：A 点在中央广场炮击区内 → 占 A 必须"炮击窗口躲、窗口后回" → A 点不再是无脑站桩，变成**节奏型据点**（与夜港"断电冲点"、荒漠"水塔续航"形成三种不同的占点体验）；
- 反制剧本：进攻方算准炮击窗口先撤 → 防守方以为安全回点 → 下轮炮击正好落点 → 双方在"赌炮击"中博弈。

### 4.5 联机最小集成建议
- 空投/炮击均为**房主权威定时器**：广播 `{k:'drop', x, z, phase:'beacon'|'land'}`、`{k:'arty', x, z, phase:'warn'|'hit'}`；
- 落弹伤害复用 `areaDamage(pos, radius, maxDmg, owner=null, team=null)`（环境伤害，不归属任何队，不触发 AI 不炸队友）；
- 补给箱实体由房主生成/销毁，同步拾取事件 `{k:'crate', id}`。

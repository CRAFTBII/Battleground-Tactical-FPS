## 0. 设计原则

1. **不改变赢法**：比分制保留（时间到比分高者胜）。缩圈是叠加在占点/击杀之上的**时间压力层**，不替代 A/B/C 占领、不产生比分、不改结算（`Game.endMatch` 不变）。
2. **与三图专属机制共存**：沙暴（desert）/ 探照灯断电（port）/ 空投炮击（suburb）照常运行，缩圈**不修改、不豁免**任何专属机制；伤害可叠加（圈外 + 风暴暴露 = 双压，是预期戏剧性）。
3. **同心圆收缩（v1.3 契约）**：`zone.center` 固定，半径按 `phases` 逐阶段缩小。**不做移动圈**（蓝圈向新位置平移）——移动圈进 backlog，待后续版本评估（需 phase 级 center 扩展）。
4. **紧迫感而非必死**：圈外伤害按阶段递增，但设计目标是把玩家"赶进圈"，不是"毒死所有人"——比分制下玩家还要继续打，圈外伤害最高档也不应秒杀满血玩家。
5. **[PLAYTEST] 标注**：半径序列 / 阶段时刻 / 伤害曲线全部待实测收敛。

## 1. schema 契约（与工程侧对齐，结构勿改）

```js
// mapDef 新增顶层字段（registry.validate 不校验它，向后兼容；缺失 = 无缩圈，游戏照常）
zone: {
  center: { x, z },                       // 圈心（固定；地图中心或偏置，见 §3）
  phases: [
    { atSec, r, dmgPerSec }, ...          // 阶段：时刻 → 半径 → 圈外每秒伤害（递增）
  ],
  warnSec: 5,                             // 每次收缩前警示秒数（固定 5，勿改）
  color: 0x4d9bff                         // 蓝圈色（三图统一，吃雞语义一致）
}
```

**阶段语义（给工程，务必一致）**：
- `phases` 按 `atSec` 升序；任意局时 `t`，取 `atSec ≤ t` 的**最后一个**阶段 = 当前生效阶段（半径 `r`、圈外伤害 `dmgPerSec`）。
- 当 `t` 到达下一阶段的 `atSec`：**atSec 前 `warnSec` 秒开始警示**（蓝圈闪烁 + banner）→ **atSec 立即开始收缩**（2s lerp 缩到新 `r`），伤害即时切换为新档（紧迫感即时生效）。
- `phases[0].atSec = 0`：开局即生效（初始圈，覆盖全图，伤害最低档）。
- 最后一个阶段持续到对局结束（600s，`CFG.MATCH_TIME`），不再收缩。

**圈外判定**：单位与 `center` 的水平距离 `d > r` → 圈外 → 每秒受 `dmgPerSec` 伤害（`Game.applyDamage(u, dmg, null, false)`，owner=null 环境伤害：不归属队伍、不触发 AI 仇恨链、不污染比分——与沙暴暴露伤害同款）。

**数值单位**：半径/坐标 = 米（m），时刻 = 秒（s），伤害 = HP/s（玩家 HP100）。

## 2. 三图缩圈数值（定稿 + [PLAYTEST]）

### 2.1 阶段时序（三图统一时间轴）

对局 600s，5 阶段（含初始圈），收缩时刻与伤害曲线三图一致（差异只在半径绝对值，因图尺寸不同）：

| 阶段 | atSec | 说明 | 圈外伤害 dmgPerSec | 设计意图 |
|------|-------|------|-------------------|---------|
| P0 | 0 | 初始圈（覆盖全图） | 1 | 象征档：开局全员在圈内，仅极端角落会碰 |
| P1 | 90 | 第一次收缩 | 3 | 可承受档：HP100 站圈外 30s+ 才危险；与 desert 沙暴首爆同刻（90s） |
| P2 | 210 | 第二次收缩 | 6 | 警告档：站圈外 15s 掉 90；被压迫者必须动 |
| P3 | 330 | 第三次收缩 | 10 | 危险档：站圈外 8s 掉 80；圈内开始"挤" |
| P4 | 450 | 最终圈 | 15 | 高压档：站圈外 5s 掉 75；最终圈决战 |

> 阶段间隔 90~120s：与据点产分节奏（2s/tick）、空投 60s、炮击 45s、沙暴 120s 周期对齐的"分钟级节拍"，玩家有充足时间理解与应对。**首缩 90s** 保证开局有 90s 纯占点热身（与 desert 沙暴首爆一致，机制不同时开压）。

### 2.2 半径序列（按图）

初始圈半径 = 覆盖全图（圈心到最远角 + 余量）；后续半径 = 初始 × 收缩比（0.62 / 0.40 / 0.26 / 0.14）。

| 图 | size | 圈心 center | P0 r0 | P1 r | P2 r | P3 r | P4 r（最终） |
|----|------|------------|-------|------|------|------|-------------|
| **suburb 城郊** | 300 | **(150,150) 居中** | 220 | 136 | 88 | 57 | **31** |
| **port 夜港** | 260 | **(165,150) 偏红侧** | 230 | 143 | 92 | 60 | **32** |
| **desert 荒漠** | 340 | **(110,140) 偏蓝侧** | 315 | 195 | 126 | 82 | **44** |

> 半径核对（[PLAYTEST] 重点）：
> - suburb r0=220 ≥ 中心(150,150)→最远角(0,0) 距离 212 ✓ 全图在圈内。
> - port r0=230 ≥ 圈心(165,150)→最远角(0,0) 距离 ≈223 ✓。
> - desert r0=315 ≥ 圈心(110,140)→最远角(340,340) 距离 ≈305 ✓。
> - 收缩位移最坏情况 ≈ 相邻半径差（desert P1: 315→195 差 120m → 冲刺 15.4s / 步行 27s），配合伤害档（3 HP/s）→ 全程暴露 46~81 伤害，可承受但必须及时动。

### 2.3 最终圈位置 rationale（偏置博弈）

| 图 | 最终圈覆盖 | 设计意图 |
|----|-----------|---------|
| **suburb** | 圈心 (150,150) r31 → **中央广场 A 点** | 基准图 = 公平终局，A 点大决战（与"均衡基准"定位一致） |
| **port** | 圈心 (165,150) r32 → **C 点(186,164) 附近（红侧主场）** | 终局偏向红侧：蓝方需长途奔袭，红方拥主场；与 port 快节奏"偏置压迫"叙事一致 |
| **desert** | 圈心 (110,140) r44 → **B 点(96,118) 附近（蓝侧主场）** | 终局偏向蓝侧：红方需长途奔袭；与 port 方向相反，避免两图终局同侧 |

> 偏置仅体现为"圈心选位"（同心圆），不是移动圈。三图最终圈都覆盖**至少一个据点 + 周边交火空间**，保证终局有据点争夺而非纯对枪。

## 3. 圈外伤害与存活核算

| 档位 | dmgPerSec | 满血(100HP)在圈外可撑 | 与步行速度对照 |
|------|-----------|---------------------|---------------|
| P0 | 1 | 100s | 出生区 → 圈心最远 178s（象征性） |
| P1 | 3 | 33s | 半径差 68~120m → 冲刺 8.7~15.4s（可承受） |
| P2 | 6 | 16.7s | 半径差 51~69m → 冲刺 6.5~8.8s（警告） |
| P3 | 10 | 10s | 半径差 32~44m → 冲刺 4.1~5.6s（危险） |
| P4 | 15 | 6.7s | 半径差 28~38m → 冲刺 3.6~4.9s（高压，需提前动） |

**设计红线**：最高档 15 HP/s 不秒杀（6.7s 才死），但"圈外 5s + 敌方火力"足以致死 → 惩罚明显、可反制（进圈即可）。禁止上调至 25+（会把比分制拖成"毒圈吃雞"）。

## 4. 警示与视觉（给美术/工程）

### 4.1 时序警示（warnSec=5，契约固定）
- 每阶段 `atSec` 前 `warnSec=5s`：**蓝圈闪烁 5s**（地面环带透明度 0.2→0.7 闪烁）+ banner「⚠ 安全区即将收缩」+ 小地图蓝圈高亮。
- 收缩动画：警示结束后 **atSec 立即开始收缩**，圈 2s 内从当前 `r` 线性插值到新 `r`，收缩同时伤害已切新档。

### 4.2 圈边缘视觉（蓝圈）
- **地面蓝环**：`RingGeometry(r-0.5, r)` 贴地，MeshBasicMaterial 蓝 `0x4d9bff`、半透明（opacity 0.35）、depthWrite:false（与炮击警示环同技术栈）。
- **半透明蓝幕**：圆柱/半球薄壳（高 ≥ 12m，可缩放到圈半径），内部看外为淡蓝渐变——标识"边界"（可选，若性能敏感可只留地面环）。
- **小地图**：圆环（半径 r 蓝圈），与 minimap 同屏渲染。

### 4.3 圈外玩家反馈
- HUD 持续警示「⚠ 你已脱离安全区 −X HP/s」+ 屏幕边缘蓝色闪光（伤害 tick 时加重）。
- 玩家从圈外进圈：HUD 提示「✓ 已进入安全区」。

## 5. 与三图专属机制共存（边界确认）

| 机制 | 共存规则 |
|------|---------|
| port 探照灯+断电 | 缩圈独立运行；灯扫 + 圈外 = 双压。断电只影响光照，不影响圈半径/伤害。 |
| desert 沙暴+水塔 | **伤害可叠加**：圈外且风暴暴露 = `dmgPerSec + exposeDmg`（预期戏剧性时刻）。沙暴 shelter 判定（建筑/水塔圈）**不豁免缩圈伤害**——缩圈是"位置压力"，躲建筑不能躲圈。水塔占领回血在圈外仍生效（可作圈外续航支点，但回血 5/s < 圈外 P3 后 10~15/s，不能赖圈外）。 |
| suburb 空投+炮击 | 空投点若在圈外：玩家自行判断值不值得抢（新增博弈：圈外空投 = 高风险高回报）。炮击 zone（中央广场）与 suburb 最终圈（居中）重叠：终局 = 炮击 + 缩圈双压 A 点，属预期难度。 |

**通用**：缩圈环境伤害 `owner=null` → 不触发 AI 仇恨链、不污染比分、不算击杀（与沙暴/炮击一致）。

## 6. AI 进圈需求（工程实现指引）

> 目标：圈外 AI 不傻站/不送头，把进圈纳入行为优先级。工程在 `js/ai.js` 的 `AIBrain` 内实现；**设计侧给出需求与优先级，不写代码**。

### 6.1 优先级规则（从高到低）
1. **圈外 + 无敌意（无可见敌人）** → 最高优先级进圈：覆盖 `squad` 目标，dest = 圈内最近可达点（或圈心），`followOrder` 顶部拦截。
2. **圈外 + 有可见敌人** → **已实现为：不打断战斗（`engage` 优先，走位/交战完全不受扰），与架构 zone-architecture.md §4 一致**。设计签认此取舍：避免「打架中途逃跑」破坏战术；圈外伤害 P1~P2 档（3~6 HP/s）下短交战不致死，战斗结束（目标消失/被击杀）后自然回 advance → 触发进圈检查，仍会进圈。圈外长时间缠斗致死属预期风险（AI 需自担圈外战斗代价）。
3. **圈内** → 完全维持现状（squad 目标 / 占点 / 拾取 / 交战照旧）。
4. **复活后**：`respawnAI` 出生点若已在圈外 → 直接以圈心为初始 dest（不走占点路线，先进圈）。

### 6.2 实现建议（给工程）
- `Mechanics` 或独立 `Zone` 模块提供：
  - `isOutside(x, z)`：`dist2(x,z,center) > r²`（r = 当前阶段半径）。
  - `nearestSafe(x, z)`：从 `(x,z)` 向 `center` 方向逐 CELL（2m）步进，返回第一个 `in-circle && World.walkable` 的点——即圈外 AI 的进圈目标（沿射线投影，天然避坑）。
- 接入点：`AIBrain.update` → `followOrder` 之前（`tryLoot` 之后）插入圈外检查；进圈目标走既有 `findPath` 寻路（2D 地面导航，无需新路径算法）。
- **红队迫击炮**（`Game.aiMortarFire`）为全局支援，不受缩圈影响（炮弹不判圈）。

### 6.3 桥梯与 AI 通行性标注（A* 是 2D 地面导航，重要）
| 元素 | AI 可通行 | 说明 |
|------|----------|------|
| **bridge 桥面（y=6m）** | ❌ AI 不上桥 | A* 走地面；桥面为 `platforms`（玩家可站）。AI 沿桥下地面绕行（依赖 §7 桥面 collider 分流）。 |
| **stairs 台阶（12×12×6）** | ❌ AI 不爬台阶 | 台阶 collider 实体块 → 导航绕行；玩家可逐级跳跃登顶（每级 1.5m ≤ 跳跃 2.3m）。台阶是"玩家专属竖向通路"。 |
| bridge 桥墩 / 既有建筑 | ✅ 绕行 | 实体 collider，AI 寻路自然绕开。 |
| wall / container | ✅ 绕行 | 同建筑处理。 |

### 7.2 桥梯设计规则（硬约束自证，见 test/port-density-probe.js）
1. **bridge 一律 `ry:0`**（BuildingLib 碰撞不随 ry 旋转——视觉转但碰撞不转 = 错位；桥只能沿 x 方向架 30m 长）。
2. **stairs 顶平台与桥面同高（y=6m）且在桥端 x 重叠 ≥2m** → 玩家可"台阶顶 → 桥面"无缝走上（已验证每座桥两端重叠）。
3. **桥墩（两端 1.2m 宽）落在主街/主道外侧** → 桥墩不堵主街中线；桥面跨街。
4. **stairs 全部放街边，不侵入主街矩形**（port x≥123 / desert x≥161 / suburb x≥137 为红线）。
5. **新增建筑避开出生点、既有建筑/掩体碰撞盒**（port N14 由 (150,60)→(150,96)、N10 由 (196,104)→(216,104) 为让位）。
6. **A* 全连通（20 出生点 × 3 据点双向 120 条）+ 主街端到端 + 出生点零重叠** 由探针断言；**探针全绿依赖 §7.3 的桥面 collider 分流**。

### 7.3 ⚠️ 关键工程联调项：bridge 桥面必须走 overhead（不挡走位/导航）
- `BuildingLib.build` 的 bridge colliders 中：**桥面 + 栏杆**（模型坐标 y≥9.6，缩放后 min.y≥5.76 ≥ OVERHEAD_Y=2.2）若直接进 `World.colliders`，会因 `buildNavGrid` 把 collider 的 xz 投影全标 blocked → **桥下地面被标记不可走 → 主街被堵、A* 断**。
- **工程方案（最小改动）**：在 `World.placeModelBuilding` 对 `key==='bridge'` 的 collider 按 `min.y` 分流——`min.y ≥ OVERHEAD_Y` 的（桥面/栏杆）推入 `World.overhead`（只挡弹道），其余（桥墩）照旧进 `World.colliders`。**仅 bridge 特殊处理，其他 key 维持现状（零回归）**。stairs 台阶（四级实心块）保持全部进 colliders（人不能穿台阶，AI 绕行合理）。
- **验收**：该分流落地后 `node test/port-density-probe.js port|desert|suburb` 三图全绿（主街端到端 + 120 条全连通）。未分流前探针预期 FAIL（仅桥面导致）——**不是布局错误，是工程分流未落地**。

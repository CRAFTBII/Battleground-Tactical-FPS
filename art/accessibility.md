# 可访问性标准（美术圣经 · 附录 D）

> 适用范围：`js/world.js`（据点视觉）、`js/game.js`（据点归属色/横幅）、`js/ui.js`（HUD/小地图/记分板）、各 `js/maps/*.js`（env 光照）
> 关联：`art/theme-atmosphere.md` §5 主题化红线、`art/building-fidelity.md` §6 backlog
> **本文档的 §3 与 §4 是硬门槛，不是建议。** UX/HUD 规格必须引用本分级。

---

## 1. 分级判定

| 分级 | 判定 |
|------|------|
| Basic | — |
| **Standard（本项目采用）** | ✅ |
| Comprehensive | 后续目标 |
| Exemplary | 不在范围 |

**为什么是 Standard**：本作是单人 + 局域网小规模对战，**无对白、无叙事文本**（不需要字幕系统），核心可访问性风险高度集中在**视觉可辨识性**——夜景可读性、队伍色识别、HUD 对比度。这三项做到位即达 Standard。
**未纳入本期的 Comprehensive 项**：完整输入重映射、字幕/音频可视化、UI 缩放系统、辅助瞄准。这些属于工程/设计范围，列在 §6 待排期。

## 3. 夜景可读性红线（port 专项）

夜景地图最大的失败模式是「玩家看不清地面 → 迷路 → 弃局」。以下为**不可突破**的硬门槛。

### 3.1 光照下限

| 项 | 红线 | port 建议值 | 出处 |
|----|------|-----------|------|
| `ambient.intensity` | **≥ 0.30** | 0.45 | 暗部不得死黑，否则阴影里的敌人不可见 → 对局失公平 |
| `hemi.intensity` | ≥ 0.40 | 0.55 | 保证人物有基本的上下光分离 |
| `fog.far` | **≥ 120** | 170 | 低于此值据点间失去视觉联系 |
| 可通行地面相对亮度 Y | **≥ 0.035**（≈ `#2a2f36`） | — | 玩家必须能看清落脚点与掩体边缘 |
| 建筑 vs 背景明度差 | **≥ 0.15** | 靠 `background` 暗于 `fog` 达成 | 保住剪影 |

**验证方法（可执行）**：`?map=port` 进图，在三个据点各截一张图，用取色器采样「路面中央」「建筑背光面」「天空」三点，换算相对亮度 Y 核对上表。

### 3.2 导航冗余（至少满足 3 条）

夜里地形辨识失效，必须提供**不依赖光照**的导航线索：

1. ✅ **高亮路面标线** —— `roads.markColor = 0xffe08a`，`MeshBasicMaterial` 不受光，天然是夜间引导线。**成本 0，收益最高，必做。**
2. ✅ **色区导航** —— 每个据点周边只用一种集装箱主色（A 蓝 `#2f6f8f` / B 锈红 `#b4442f` / C 黄 `#d1a02c`），玩家靠「我在什么颜色的箱区」定位。
3. ⚙ **据点旗杆顶灯** —— 旗杆顶加一个 `MeshBasicMaterial` 小球（队伍色），夜里作为远距离信标。
4. ✅ **路灯光斑** —— 地面暖黄矩形（`MeshBasicMaterial`），既是氛围也是路标。**前置：bulb 必须先改成 `MeshBasicMaterial`（backlog D-12），否则路灯在夜里等于不存在。**
5. ⚙ **超大剪影地标** —— 龙门吊（见 `glb-slot-conventions.md` §6），全图任意位置可见。

### 3.3 敌我识别（夜景最大风险）

**问题**：士兵模型用 `MeshLambertMaterial` + 顶点色（`models.js`），夜景下会随环境一起变暗 → **红蓝队伍色在暗处失效，友军误伤率飙升**。

**建议方案**（按成本排序，至少落地 1）：

| 方案 | 做法 | 成本 | 副作用 |
|------|------|------|-------|
| **A（推荐）** | 单位脚下一个 `RingGeometry` + `MeshBasicMaterial`（队伍色，`opacity 0.5`，`depthWrite:false`），**仅对当前可见（未被 `rayBlocked` 遮挡）的单位显示** | 低 | 若不做可见性剔除会给玩家透视外挂优势 —— **必须做剔除** |
| **B** | 士兵身上一小块不受光的队伍色标（肩章/头盔条），`MeshBasicMaterial` | 中（要改模型部件） | 无 |
| **C** | 提高 `ambient.intensity` 到 0.6+ | 0 | 夜景氛围被冲淡，不推荐单独使用 |

## 4. 队伍色与色盲友好（P0 · 当前存在明确缺陷）

### 4.1 现状与量化诊断

现有色值（相对亮度 Y 按 WCAG 公式计算：sRGB → 线性 → `0.2126R + 0.7152G + 0.0722B`）：

| 位置 | 蓝方 | Y | 红方 | Y | 中立 | Y | **蓝红对比度** |
|------|------|---|------|---|------|---|--------------|
| 3D 据点环/旗（`game.js:80`） | `#2e6fd8` | 0.185 | `#d03a2e` | 0.166 | `#9aa0a8` | 0.348 | **1.08 : 1** ❌ |
| HUD / 小地图（`ui.js:123,194,197,220`） | `#3d9bff` | 0.316 | `#ff4d4d` | 0.271 | `#8a93a0` | 0.277 | **1.14 : 1** ❌ |
| 记分板 / 横幅（`game.js:65,206`，`ui.js:152`） | `#7ec8ff` | — | `#ff8a8a` | — | — | — | 同类问题 |

**诊断**：红与蓝的**相对亮度几乎完全相同**。红绿色盲（deuteranopia / protanopia，约占男性 8%）主要依赖明度通道区分颜色 —— 对比度 1.08:1 意味着**这部分玩家在灰度上完全无法区分敌我据点**。这是 P0 级可访问性缺陷，也是普通玩家在 port 夜景低照度下同样会遇到的问题。

**次要问题**：现有 3D 中立灰 `#9aa0a8`（Y 0.348）**比蓝方还亮**，视觉权重错误——中立态不该是画面里最醒目的。

### 4.2 修正规范

#### 默认配色（Normal）—— 靠明度分离

| 状态 | 色值 | 相对亮度 Y | 说明 |
|------|------|-----------|------|
| 蓝方 | **`#5aa9ff`** | 0.378 | 提亮 |
| 红方 | **`#b3261e`** | 0.111 | 压暗 |
| 中立 | **`#707880`** | 0.184 | 降到蓝红之间且降低不透明度 |

- 蓝 vs 红对比度 = **2.66 : 1** ✅（从 1.08 提升 2.5 倍，灰度下深浅一目了然）
- 中立 vs 蓝 = 1.82:1、中立 vs 红 = 1.46:1 → **三态无法只靠明度分开**，所以中立态**必须**叠加形状/透明度区分（见 §4.3）。这是诚实的取舍，不是遗漏。

#### 色盲模式（CVD）—— 靠安全色相轴分离

| 状态 | 色值 | Y | 说明 |
|------|------|---|------|
| 蓝方 | **`#4dc3ff`** | 0.478 | 青蓝 |
| 红方 → 橙 | **`#ffa63d`** | 0.489 | 橙 |
| 中立 | **`#707880`** | 0.184 | 明显更暗 |

蓝–橙是对 deuteranopia / protanopia / tritanopia **三类都安全**的色相轴（这也是主流射击游戏色盲模式的通用解）。此模式下中立态靠明度即可分离（对比度 vs 蓝 ≈ 2.26:1）。

### 4.3 形状编码（**始终开启**，不随模式切换）

颜色是辅助信道，形状才是主信道。以下编码在两种配色模式下都生效：

| 元素 | 蓝方 | 红方 | 中立 |
|------|------|------|------|
| 3D 据点地面环 | **实心连续环**，`opacity 0.45` | **8 段虚线环**，`opacity 0.45` | **细线空心环**，`opacity 0.20` |
| 3D 旗面 | **实心矩形旗** | **燕尾旗**（带三角缺口） | **无旗 / 极小灰三角** |
| 小地图据点 | **实心圆** | **实心方块** | **空心圆** |
| 小地图单位 | 实心圆（玩家自己：圆 + 十字准心） | 实心方块 | — |
| HUD 据点条 | `A●` | `A■` | `A○` |

实现成本极低：小地图是 canvas 2D（`arc` vs `fillRect`），3D 虚线环可用 8 个 `RingGeometry` 扇段或一张带透明段的程序化贴图。

### 4.4 不受光要求

| 元素 | 当前材质 | 要求 |
|------|---------|------|
| 据点地面环 | `MeshBasicMaterial` ✅ | 保持 |
| 据点旗面 | `MeshLambertMaterial` ❌ | **改 `MeshBasicMaterial`**（backlog D-13）——否则 port 夜景下旗色被压暗，队伍归属不可辨 |
| 旗杆 | `MeshLambertMaterial` | 可保持（非信息载体） |
| 单位队伍标识（若采用 §3.3 方案 A/B） | — | 必须 `MeshBasicMaterial` |

### 4.5 单一数据源（P1）

现状：队伍色硬编码分散在 **~10 处**（`game.js:44/65/80/156/206`、`ui.js:123/152/194/197/220`、`world.js:buildCapturePoints`）。任何配色调整都要改 10 个地方，色盲模式无从实现。

建议在 `core.js` 增加：

```js
CFG.TEAM_COLORS = {
  normal: {
    blue:    { hex: 0x5aa9ff, css: '#5aa9ff', shape: 'solid'  },
    red:     { hex: 0xb3261e, css: '#b3261e', shape: 'dashed' },
    neutral: { hex: 0x707880, css: '#707880', shape: 'hollow' }
  },
  cvd: {
    blue:    { hex: 0x4dc3ff, css: '#4dc3ff', shape: 'solid'  },
    red:     { hex: 0xffa63d, css: '#ffa63d', shape: 'dashed' },
    neutral: { hex: 0x707880, css: '#707880', shape: 'hollow' }
  }
};
```
配合 URL 开关 `?cvd=1` 或设置项切换。**这是实现色盲模式的前置条件。**

## 5. HUD / 文本对比度

| 元素 | 要求 | 备注 |
|------|------|------|
| 正文（记分板、提示） | 与背景对比度 **≥ 4.5 : 1** | WCAG AA |
| 大字（横幅、比分、计时） | **≥ 3 : 1** | WCAG AA Large |
| 血条 | 三档色 `#2ecc71 / #f1c40f / #e74c3c` 现状可接受，但**必须叠加数值或分段刻度** | 纯颜色表达血量对色盲不友好 |
| 击杀/受击反馈 | 不得**只**用颜色 | 需配合图标/位移/音效 |
| 半透明面板 | 必须有实底或描边 | 避免叠在亮天空（desert）上时文字消失 |

> ⚠ **desert 专项**：背景是高亮米黄（`#e6d4ae`，Y ≈ 0.65）。任何浅色 HUD 文字在天空前会消失。**desert 图的 HUD 元素必须有深色底板或 1px 深色描边。**

## 6. 验收清单（每图交付前逐条过）

**通用**
- [ ] 灰度截图测试：把游戏截图转灰度，红蓝据点/旗/小地图图标**仍能区分**（明度差 + 形状）
- [ ] 色盲模拟测试：用 deuteranopia / protanopia / tritanopia 三种滤镜看同一截图，敌我仍可辨
- [ ] 队伍色未被任何主题覆盖（三图一致）
- [ ] 据点视觉元素全部 `MeshBasicMaterial`
- [ ] HUD 正文对比度 ≥ 4.5:1（取色器实测）

**port 夜景专项**
- [ ] 三个据点各截图，路面/建筑背光面/天空的相对亮度符合 §3.1
- [ ] 从任一出生点出发，不看小地图能在 30 秒内找到最近据点（导航冗余 §3.2 生效）
- [ ] 站在暗处的敌人在 25m 内可被发现（§3.3 方案已落地）
- [ ] 路灯可见（bulb 已改 `MeshBasicMaterial`）

**desert 专项**
- [ ] HUD 文字在朝天空的机位下仍清晰（深色底板/描边）
- [ ] 高亮沙地不产生眩光级过曝（远处不应出现纯白 `#ffffff` 区块）

## 1. 可见度预算（一切尺寸规范的推导基准）

FPS 交战距离主要落在 **15–60m**。以 1080p、竖直 FOV ≈ 60° 估算，1 像素张角 ≈ 0.00097 rad：

| 观察距离 | 1 像素对应实际尺寸 | 结论 |
|---|---|---|
| 15 m | 0.015 m | 0.1m 细节 ≈ 7 px，清晰 |
| 30 m | 0.029 m | 0.1m 细节 ≈ 3.4 px，勉强可辨 |
| 60 m | 0.058 m | 0.1m 细节 < 2 px，消失 |

**规范 R1（最小尺寸）**：任何精修部件的最小边 **≥ 0.10 m**。低于此值等于白烧顶点。
**规范 R2（轮廓件）**：期望在 30m 外仍参与剪影识别的部件（檐口、阳台、烟囱、角柱）最小边 **≥ 0.25 m**。
**规范 R3（游戏化放大）**：出挑类尺寸相对真实建筑放大 **1.5–3×**（真实窗台出挑 5–10cm，本项目 30cm）。这是刻意的，不是错误——目的是在 30m 外还能读出阴影线。
**规范 R4（不做的事）**：< 0.08m 的线脚、真实厚度的窗框玻璃压条、砖缝级凹凸——一律交给程序化纹理，不做几何。

## 2. 精修部件清单与几何/比例规范

下表中「当前实现值」严格取自 `js/world.js`，「规范公式」是本文档给出的可推广规则（新建筑/新地图按公式取值，与现值保持一致）。

### 2.1 洞口与框料

| 部件 | 规范公式 | 当前实现值 | 状态 |
|------|----------|-----------|------|
| 窗洞 | `Ow = 1.4`、窗台高 `1.1`、`Oh = 1.2`（y 1.1→2.3） | 硬编码于 `buildBuilding` | ⚠ 建议参数化 |
| 窗位 | 每面均分：`cu = len/(ws+1)*k - Ow/2` | 一致 | ✅ |
| 门洞 | `Oh = opts.doorH`（默认 2.6）；净宽建议 1.6–2.0 | 由 `opts.doors[[u0,u1]]` 给 | ✅ |
| 窗框料宽 `bw` | `0.09·Ow`，夹到 `[0.10, 0.18]` | `0.13`（0.09×1.4 = 0.126） | ✅ 吻合 |
| 门框料宽 | `0.09·Ow`，下限 `0.15` | `0.17` | ✅ |
| 框料外凸 `fd` | `1.15·bw`，且 `≤ 0.4t` | 窗 `0.15` / 门 `0.18` | ✅ |
| 框料贴墙偏移 | `oc = t + fd/2 - 0.03`（留 3cm 咬入防缝） | 一致 | ✅ |
| 上/下冒头长 | `Ow + 2·bw`（框口交圈） | 一致 | ✅ |
| 立梃高 | `Oh + 2·bw` | 一致 | ✅ |

**窗台高度红线（美术 × 玩法）**：窗台高必须落在 **[0.90, 1.25] m**。
低于 0.90 → 蹲伏姿态仍露头，窗户失去掩体价值；高于 1.25 → 站立（EYE 1.7）无法舒适俯射。当前 1.1 位于区间中点，**不要改动**。

### 2.2 线脚与体块

| 部件 | 规范公式 | 当前实现值 | 状态 |
|------|----------|-----------|------|
| 窗台板 | 宽 `Ow + 0.4`（每侧挑 0.2）、厚 `0.13`、外挑 `0.30` | 一致 | ✅ |
| 门楣挑檐 | 宽 `Ow + 0.7`、厚 `0.16`、外挑 `0.44` | 一致 | ✅ |
| 楼层水平分缝 | 高 `0.06·Fh ≈ 0.18`、外挑 `0.09`，位于 `y = f·Fh`（f = 1..N-1） | 一致 | ⚠ high 档建议外挑提到 **0.12** |
| 檐口 / 女儿墙压顶 | 高 `0.15·Fh ≈ 0.44`、外挑 `0.30`，位于 `y = N·Fh + 0.2` | 一致 | ✅（古典檐部 1/8–1/6 层高，比例成立） |
| 勒脚 plinth | 高 `0.6`、外挑 `0.14`、`y = 0.3` | 已实现但**默认关** | ⚠ 会横穿门洞，需按面断开 |
| 角柱 pilaster（model） | 见方 `0.45 + 2×0.12 = 0.69`，通高 `top` | 一致 | ✅ |
| 阳台挑板 | 深 `1.4`、厚 `0.18` | 一致 | ✅ |
| 阳台栏板 | 高 `1.0`、厚 `0.12`；扶手顶面 `1.17`、厚 `0.10` | 一致 | ✅（1.1m 安全栏高，符合真实规范） |
| 阳台平面 | 长 `0.5·面长`，起点 `0.25·面长`，逐层生成 | 一致 | ⚠ 默认全楼层生成，建议默认关 |
| 烟囱 | `0.9 × 0.9 × 1.9`；烟囱帽外扩 `+0.24`、高 `0.16` | 一致 | ✅（仅 `N ≤ 2` 生成） |
| 屋顶女儿墙栏（rooftop） | 高 `0.70`、厚 `0.30`，四边 | 一致 | ✅ |
| 屋顶坡道（rooftop） | 宽 `3`、长 `16`、坡角 `atan(N·Fh / 16)` | 一致 | ✅（N=2/Fh=3 → 20.6°，可跑上） |

### 2.3 环形件生成规则（`_ringBoxes`）

环形件（分缝 / 檐口 / 勒脚）由 4 段盒拼成，**必须**用建筑的外皮尺寸作为基准，否则会嵌进墙里或悬空：

- **proc 建筑**：外皮 = `W + 2t` × `D + 2t`（`addWall` 把墙贴在 `x0-t..x0` 外侧）→ 传 `sw = W + 2t, sd = D + 2t`。当前实现一致 ✅
- **model 建筑**：外皮 = `w × d`（`BuildingLib` 几何原点在角、占 `[0,w]×[0,d]`）→ 传 `sw = w, sd = d`。当前实现一致 ✅

## 3. 按建筑类型的应用规则

`BuildingLib.CONFIGS` 现有 5 种：`warehouse / apartment / house / watchtower / cover`（标称尺寸取自 `js/models.js`，实际几何包围盒由内联数据实测）。

| 类型 | 标称 W×D×H | 实测几何包围盒 | 层数/层高 | 应用精修 | 不用 |
|------|-----------|---------------|----------|---------|------|
| `warehouse` 仓库 | 22×14×8.5 | 22.0×14.0×**9.70** | 1 层 · 高大空间 | 檐口、角柱、卷帘门框（框料放大到 **0.22**）、屋顶设备（待补） | 窗台、分缝、阳台、烟囱 |
| `apartment` 公寓 | 16×12×16.6 | 16.0×12.0×**19.10** | 4 层 · `Fh = 4` | 檐口、角柱、分缝带 `[4,8,12]`、阳台（面 0，2–4 层） | 烟囱 |
| `house` 民居 | 10×8×4.3 | 10.6×8.6×4.30（含 0.3 出檐） | 1 层 · `Fh = 3` | 檐口、烟囱、窗台、门框 | 角柱、分缝、阳台 |
| `watchtower` 瞭望塔 | 4×4×8.5 | 4.2×4.2×8.50（几何**中心在原点**） | — | `trim: false`（保持通透剪影） | 全部；仅建议补顶部檐板 0.25 |
| `cover` 掩体组 | 14.5×5.7×2.6 | 14.5×6.3×2.75 | — | `trim: false` | 全部 |

**规范 R5（体量分档）**：
- `W·D < 60 m²` → 只给「檐口 + 窗台/门框」（house 档）
- `60 ≤ W·D < 250 m²` 且 `N = 1` → 「檐口 + 角柱」（warehouse 档）
- `N ≥ 2` → 「檐口 + 角柱 + 每层分缝」，`N ≥ 3` 才给阳台（2 层楼的阳台在 FPS 视角像雨棚，观感差）
- `H > 12` → 檐口高上调到 `0.60`，否则从地面仰视被透视压扁看不见

**规范 R6（烟囱归属）**：只有「民居/低层住宅」语义的建筑给烟囱（`N ≤ 2` 已在代码中限制）。仓库/公寓/塔不给。港口主题用**排气管/风机**替代（待补部件），沙漠主题用**风塔/女儿墙垛口**替代。

## 4. detail 等级映射（当前实现的真实行为）

`World.DETAIL = { off:0, none:0, low:1, high:2, full:2 }`，地图级 `mapDef.detail`，建筑级 `opts.detail` / `trim:false` 覆盖，URL `?detail=` 强制。

### 4.1 proc 建筑（`buildBuilding`）

| 等级 | 生成的部件 |
|------|-----------|
| **0 off** | 裸墙 + 楼板 + 屋顶板（+ 室内家具 + rooftop 栏杆坡道，注意这两者不受 detail 控制） |
| **1 low** | + 窗台、门楣挑檐、楼层分缝环、檐口压顶（+ 勒脚，若 `plinth:true`） |
| **2 high** | + 窗框/门框（立梃 ×2 + 上冒头 + 窗下冒头）、阳台（`N ≥ 2` 且 `balcony !== false`）、烟囱（`N ≤ 2` 且 `chimney !== false`） |

### 4.2 model 建筑（`placeModelBuilding` → `buildModelTrim`）

| 等级 | 行为 |
|------|------|
| **0 off** | 不生成任何 trim |
| **1 low** | **生成 trim 的全部内容**（檐口 + 角柱 + 分缝 + 烟囱，由 `trim` 对象的布尔位控制） |
| **2 high** | 与 low **完全相同**（`buildModelTrim` 内部无 lvl 分支） |

> ⚠ **差异点**：model 建筑没有 low/high 分档，`?detail=low` 对它不降载。见 §6 backlog D-14。

### 4.3 各图 detail 推荐

| 地图 | 推荐 `detail` | 理由 |
|------|--------------|------|
| suburb | `high` | 基准图，白天全开 |
| port | `high` | 夜景靠**剪影 + 边缘线脚反光**建立可读性，降档会让建筑糊成黑块 |
| desert | `high` | 强侧光下线脚投影是主要质感来源 |
| 低端设备 | `?detail=low` | 保留窗台/檐口/分缝（贡献 80% 观感），砍掉窗框/阳台（贡献 60% 顶点） |

## 5. 性能预算

| 指标 | 预算 | 当前状态 |
|------|------|---------|
| 单栋建筑 draw call | **≤ 4**（墙 1 + 楼板 1 + 屋顶 1 + 细节 1） | ❌ 超标：`addWall` **每段墙一个 Mesh**，4 面 ×(窗数+1) 段 × 层数，一栋 3 层 3 窗的建筑 ≈ **48 个墙 mesh** |
| 全图建筑 draw call | ≤ 60 | 需实测（suburb 全为 model 建筑，每栋 2–3 call，尚在预算内） |
| 单栋细节盒数 | ≤ 400（合批后 9.6k 顶点，`Uint16` 索引上限对应 2730 盒，安全） | ✅ 现实用量 < 120 |
| 共享材质总数 | ≤ 20 | ✅ `sharedMat` 缓存 |
| 程序化纹理 | ≤ 12 张 256²（当前 8 个 key） | ✅ |
| GLB 总面数 | ≤ 80k tris（见 `glb-slot-conventions.md`） | 当前 0（GLB 未启用） |

**规范 R7**：墙段几何**应当也合批**——碰撞体是纯数据（AABB 数组），与 Mesh 完全解耦，合批不影响玩法。见 backlog D-11。

## 6. 差异清单：当前实现 vs 理想（工程精修 backlog）

图例：✅ 已实现且正确 · ⚠ 已实现但有缺陷 · ❌ 缺失
优先级：**P0** 视觉/玩法明显错误，必须修 · **P1** 明显提升精细度 · **P2** 锦上添花

### 6.1 ⚠ 缺陷类（先修这些，比加新部件收益高得多）

| ID | 项 | 现象与证据 | 影响 | 优先级 |
|----|----|-----------|------|-------|
| **D-01** | 多层 proc 建筑**上层窗洞被底层墙填死** | `buildBuilding` 每层的墙段都取 `y1 = h - fy`（一直建到建筑顶），所以 f=0 层在窗区上方生成了 `2.3 → h` 的整块墙，把 f=1..N-1 层的窗洞全部堵住 | 多层程序化建筑**只有一层有窗**，且窗上方是死墙 | **P0** |
| **D-02** | 墙段跨层重复生成 | 同上：f=0 建 `0→h`，f=1 再建 `Fh→h`，f=2 再建 `2Fh→h`，完全共面重叠 | z-fighting 闪烁；`overhead` AABB 冗余（弹道检测多跑 N 倍）；draw call 翻 N 倍 | **P0** |
| **D-03** | model 建筑 `ry ≠ 0` 时**视觉与碰撞错位** | `BuildingLib.build` 里 `mesh.rotation.y = ry` 但碰撞盒用未旋转的 `x + c[0]`（代码注释已自认「ry 暂仅视觉，碰撞不旋转」）。几何原点在角（实测 apartment/warehouse 包围盒 min = 0,0,0），绕角旋转 90° 后 footprint 落到另一象限。<br>例：suburb `apartment x:200 z:52 ry:90 w:16 d:12` → 视觉 footprint ≈ x[200,212]·z[36,52]，碰撞 x[200,216]·z[52,64]，**两者不相交** | 玩家撞空气 / 穿建筑；小地图与实景不符；精修 trim 跟着 `ry` 转，也和碰撞脱节 | **P0** |
| **D-04** | `watchtower` 几何中心与碰撞角点差 2m | 实测包围盒 `min(-2,-2,0) max(2.2,2.2,8.5)`（几何居中），而 `CONFIGS.watchtower.colliders` 是 `[0,4]×[0,4]`（角点系） | 塔腿视觉与碰撞整体偏移 2m，玩家「站在塔外的空气平台上」 | **P0** |
| **D-05** | 阳光阴影相机只覆盖世界西南角 | `buildEnv` 里 `DirectionalLight.target` 未设置（默认 (0,0,0) 且未加入场景），`shadow.camera.extent = 130`。地图是 `[0,300]²`，中心 (150,150) 到光轴的垂距 ≈ **160 m > 130** → 落在阴影视锥外 | **全图 60% 以上区域没有投影**，建筑失去体积感；三张图都受影响 | **P0** |
| **D-06** | `trim.top` 与模型真实高度不符 → 檐口穿模 | warehouse 实测高 **9.70**，`suburb.js` 写 `trim.top: 8.0`；apartment 实测高 **19.10**，写 `trim.top: 16.0` | 檐口线脚横穿屋顶结构中部，像一条错位的腰带 | **P1** |
| **D-07** | proc 建筑 `h ≠ N·Fh` 时屋顶/檐口错位 | 墙建到 `h`，但楼板/屋顶板/檐口/阳台一律按 `N·Fh` 定位 | 屋顶悬空或埋进墙里 | **P1** |
| **D-08** | 阳台默认全开 | `if (lvl >= 2 && floors >= 2 && opts.balcony !== false)`：**不写 `balcony:false` 就会给所有多层 proc 建筑挂满阳台** | 仓库/办公楼也长阳台，主题错乱 | **P1** |
| **D-09** | `opts.balconies: []` 被就地写入 | `const list = opts.balconies || []` 后 `list.push(...)` → 直接改写 mapDef 数据对象 | mapDef 被运行时污染（数据应只读） | **P2** |
| **D-10** | 勒脚横穿门洞 | 已知 CONCERN-2，默认关 | 无法使用勒脚这个廉价质感件 | **P2** |
| **D-11** | 墙段不合批 | `addWall` 每段 `new THREE.Mesh` | draw call 随窗数×层数线性增长 | **P1** |
| **D-12** | 路灯灯泡不发光 | `buildProps` 里 bulb 用 `MeshLambertMaterial(0xffe9a8)` | 夜景（port）下灯泡变成暗黄色小球，「灯」的语义消失 | **P1**（port 阻塞项） |
| **D-13** | 据点旗面受光照影响 | `buildCapturePoints` 里 flag 用 `MeshLambertMaterial` | port 夜景下红/蓝旗色被压暗，队伍归属难辨（见 `accessibility.md`） | **P1** |
| **D-14** | model 建筑无 low/high 分档 | `buildModelTrim` 内无 lvl 分支 | `?detail=low` 对现有 suburb（全 model）不降载，性能开关失效 | **P2** |
| **D-15** | model 建筑无法主题化染色 | 主体材质是 `MeshLambertMaterial({vertexColors:true})`，颜色烘死在 `BUILDINGS_DATA` 里 | 同一栋 house 在 suburb/port/desert 长得一模一样 → 三图视觉语言无法拉开 | **P0**（主题化阻塞项，见 §6.3） |

### 6.2 ❌ 缺失部件（按性价比排序）

| ID | 部件 | 说明与建议实现 | 成本 | 优先级 |
|----|------|--------------|------|-------|
| **M-01** | **窗玻璃面** | 现在窗洞是真空洞，从街上能一眼看穿建筑，室内漆黑、无「玻璃」语义。建议：窗洞位置加一片 `PlaneGeometry`，`MeshBasicMaterial({color: 主题天空色暗化 30%, transparent:true, opacity:0.35, depthWrite:false})`，**不产生碰撞**（子弹仍可穿窗，玩法不变） | 每窗 1 个四边形，可并入 `det` 合批（需第二个材质 → 第二个合批 mesh） | **P1** |
| **M-02** | **屋顶设备**（水箱 / 风机 / 管道 / 出屋面楼梯间） | 屋顶是本作重要战斗层（`rooftop` 平台），现在完全是一块空板，既无掩体感也无剪影。建议：3–6 个盒 + 1 个圆柱水箱，随建筑 hash 选布局。**若要当掩体必须显式推 collider**（与「精修纯视觉」原则冲突 → 建议做成独立的 `props.rooftopKit` 而非 trim） | 低 | **P1** |
| **M-03** | **雨落管** | 四角竖向细管（0.14 见方，通高），是最廉价的「竖向线」质感件，能打破大墙面的空洞 | 4 个盒/栋 | **P1** |
| **M-04** | **门扇 / 半开门板** | 门洞现在全空。加一片斜置门板（不产生碰撞） | 1 盒/门 | **P2** |

## 7. 命名与数据书写规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 程序化纹理 key | 全小写单词，无下划线 | `brick` `concrete` `sand` `corrugated` |
| `sharedMat` 名 | 复用纹理 key；纯色件用 `<语义>` 驼峰 | `furnA` `ruinWall` `pole` |
| mapDef 建筑 | 按「从大到小、从公共到边缘」排序，同类相邻，每类前加注释 | 见 `suburb.js` |
| 坐标语义 | **建筑 `x/z` = 角点（西南角）**；据点/掩体/装饰 = 中心 | map-architecture §9.2 |
| 尺寸书写 | 一律米，保留 1 位小数；`h` 必须等于 `N·Fh`（proc）或模型实测高（model） | `w:16, d:12, h:16.6` |
| GLB 文件 | 见 `art/glb-slot-conventions.md` §2 | `models/buildings/port_warehouse.glb` |

## 8. 美术验收清单（每次改建筑/加地图后逐条过）

1. 站在建筑门口 3m 处：门框/窗台/门楣线脚清晰可辨，无 z-fighting 闪烁。
2. 退到 30m：檐口、角柱、阳台、烟囱仍在剪影中可读（R2）。
3. 退到 60m：建筑靠**体量 + 檐口一条水平线**识别，细节消失属正常。
4. 绕建筑一圈：四个面都有精修，无「只做正面」的穿帮；`ry ≠ 0` 时视觉与碰撞对齐（走过去撞得到墙）。
5. 从屋顶俯视：檐口不穿屋顶（D-06），女儿墙闭合。
6. 进入室内：门洞可通行（`OVERHEAD_Y` 机制生效），窗洞可射击且窗台高度符合 §2.1 红线。
7. `?detail=off` / `low` / `high` 三档切换：无报错，无几何残留，观感递进合理。
8. `node test/smoke.js` 全绿（碰撞数不因精修变化——精修不产生碰撞）。

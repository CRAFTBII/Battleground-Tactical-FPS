## 5. 风险与建议

1. **BLOCKER 修复建议（最小改动，design §7.3 原方案）**：`World.placeModelBuilding` 对 `key==='bridge'` 的 collider 按 `min.y ≥ OVERHEAD_Y(2.2)` 分流进 `World.overhead`（只挡弹道），桥墩照旧进 `colliders`。一处改动可同时修复 ②-1、③-C/D（三图 6 项 FAIL）、⑥ 沙暴庇护误判——无需动地图数据。
2. **回归补测**：修复后应补一条「玩家/AI 移动穿过桥下」断言（非仅 A*），防止只修导航网格不改移动层再次漏检。本次已验证 A* 绿 ≠ 移动绿。
3. **CONCERNS（非阻塞，需设计/工程确认口径）**：
   - 设计 §6.1 规则 2「圈外有敌 → 走位偏圈内」未实现：实现与架构 §4 一致（engage 完全不受扰）。行为合理，但与设计文档字面有出入，需 design-strategist 确认以设计还是架构为准。
   - 设计 §1/§4.1「atSec 到达 → 警示期 warnSec 秒 → 再收缩」vs 实现「atSec-warnSec 提前警示 → atSec 立即收缩」。两者「警示→收缩」间隔均为 5s，玩家体验一致，但 atSec 语义（是警示点还是收缩点）与设计字面不同，建议设计侧统一措辞。
   - `Mechanics.zone.escapeDest` 按同心环采样（4 半径×8 角）而非设计建议的射线逐 CELL 步进，返回点可能非「严格最近」，但功能等价（圈内可达点），不阻塞。
4. **桥面残留 collider 的其它副作用**：`buildCoverPts`（game.js:86）会把桥面当掩体生成 cover 点（视觉噪声）；`_initSandstorm` 庇护误判（已证）；均随 §5.1 修复自动消失。
5. **测试稳定性**：`test/_qa_v13_zone.js` fast-forward 圈伤会打死 AI/玩家 → 测试内已加「全员复活」前置；跑两遍结果稳定（48 PASS / 34+8），无 flaky。

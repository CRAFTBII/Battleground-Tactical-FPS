# 建筑碰撞系统专项修复记录与行动指南

## 目的与边界

修复建筑视觉模型、运行时碰撞体、可站立平台、地图缩放和 AI 导航之间的不一致，重点消除墙体穿模、门洞空气墙、室内通道封闭和楼层碰撞异常。

本轮采取独立分支，不直接修改 main。任何模型碰撞盒的数值调整都必须有模型尺寸、坐标偏移和地图摆放数据作为依据；不能用扩大 AABB 的方式掩盖穿模。

## 当前已确认的工程风险

1. `tools/_gen_xl_colliders.js` 内含历史版 XL 建筑尺寸、偏移和门洞数据，原脚本会直接替换 `js/models.js` 的 v1.4 区块。
2. 旧 `tools/_validate_xl.js` 从上述生成器调用 `buildXL()`，校验的不是当前运行时 `BuildingLib.CONFIGS`；其中 META 还使用旧地图尺寸。
3. 旧 `tools/_audit_dims.js` 只识别显式 `w/d/h`，无法正确审计当前地图主要使用的等比 `scale` 模式。
4. 当前系统分别维护 `colliders`、`platforms`、`overhead` 和 2D A* 网格；墙体/门洞/楼板的语义必须分开验证。
5. 静态源码审计无法证明游戏运行时无穿模。必须在浏览器/游戏场景中进行碰撞可视化与人工走测。

## 本轮修复

- 将 XL 生成器改为只读预览，禁止旧数据写回正式模型配置。
- 将 XL 验证器改为读取 `js/models.js` 当前 `BuildingLib.CONFIGS`，检查碰撞盒与平台的数据完整性、边界和地图 scale。
- 将尺寸审计器改为识别 `scale` 与显式 `w/d/h` 两种地图定义。
- 保留所有正式建筑碰撞数值不动，等待审计结果与模型几何逐项核对后再修。

## 执行命令

```bash
node tools/_validate_xl.js
node tools/_audit_dims.js
```

旧 XL 生成器现在只输出历史数据统计并以非零状态退出，不会写入 `js/models.js`。

## 后续逐栋修复顺序

1. base：围墙四门、HQ 门洞、楼板与平台、营房和机库。
2. refinery：主厂房入口、冷却塔/烟囱 AABB 近似、检修平台。
3. stadium：环形外墙四个径向入口、入口通道和看台下方空间。
4. megatower：11 层楼板、中央楼梯井、交替隔墙和逐层可达性。
5. complex：四面入口、中庭、环廊、核心筒和四角楼梯井。

## 场景回归测试要求

- 外墙实体点必须阻挡；门洞中心与走廊中心必须可通行。
- 玩家胶囊/圆柱体沿墙滑动时不得穿墙或被无形边界卡住。
- 每层楼板必须支撑角色；楼梯井/电梯井/中庭不得被错误填充。
- 旋转与缩放后的碰撞体必须与渲染模型共用同一变换。
- AI 起点至门内、楼梯口和楼层目标的路径必须可达，路径线段不得穿过墙体。
- 射线和投射物按明确规则处理普通墙、门楣与 overhead。
- 在开发模式显示碰撞体线框，并记录复现坐标、建筑 key、collider index。

## 验收口径

自动化结构检查零 errors；所有 warnings 均有解释或修复记录；每栋建筑至少通过外墙、门洞、内部通道、楼层/平台和 AI 导航的场景测试。未运行的测试不得标记为通过。

## 当前限制

本轮通过 GitHub API 修改仓库文件；未克隆仓库，也未在浏览器或 Node.js 环境运行游戏/测试。自动化脚本需要由项目运行环境执行后，才能给出实际测试结果。

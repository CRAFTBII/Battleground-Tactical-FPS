## 3. 逐栋玩法要求

### warehouse_a · A 点情报站

- 一层大空间 + 西侧办公室；办公室必须有 **2 个门/破窗**，不能单入口。
- 货架/箱子形成两条室内视线，不能从门口一眼看穿到目标电脑。
- 猫道可上屋顶，屋顶女儿墙 1.0m；至少 2 条上下路径。
- 室内有 1 个主灯 + 天窗/高窗；目标电脑在办公室角落，交互 8s。

### admin_b · B 点指挥楼

- F0 大厅（接待台低掩体）+ F1 服务器房（目标）+ 屋顶狙击位。
- 主楼梯不能正对 2F 窗口；外消防梯提供第二条上下路径。
- 2F 服务器房 2 个入口；门口有低掩体，但不能堵死。
- 屋顶有女儿墙/设备，可从 F1 爬梯上；狙击位可被外梯/对面窗口反制。

### apartment · 中途高点

- 4 层，核心楼梯 + 外消防梯；每层至少 1 个可守窗口/阳台。
- 楼梯核心可听脚步；不在每层做迷宫。
- 顶层/屋顶提供中距离视野，但阳台暴露，必须给反制视线。

### house · 住宅

- 前后门形成穿屋路线；客厅/厨房低掩体。
- 2F 窗口可守，但窗口下有矮墙/车辆可反制。
- 直跑楼梯净宽 1.2m，楼梯口不对正门。

### townhouse · 店面住宅

- 一层店面 + 后仓，二层住宅；店门/后门两个出口。
- 店面玻璃提供短视线（后续可做可破坏）。
- 二层窗口可看街，但窗口小、易被烟雾/掩体反制。

### shop · 补给点

- 柜台/货架低掩体，后仓可藏人；前门/后门形成穿行。
- 临街玻璃形成短视线，不做长枪线。

### guardhouse / shed / container / ruin

- 只作为战术掩体/检查站，不承担主目标。
- 每个至少有一个可进入/可穿行方向；不做完全实心黑盒。
- 集装箱可单层/双层堆叠；双层时提供可上顶路径。

### wall / catwalk / crane / extraction gate

- 围墙用于界定战斗边界，留门/缺口；不做不可见空气墙。
- 猫道连接仓库/行政楼上层，栏杆可作掩体。
- 吊机是地标/远程位，爬梯可上，但暴露。
- 撤离门有绿色信号灯/闸机，触发区清晰。

## 4. 节点与锚点要求

| 资产 | 必需节点 | 必需锚点 |
|---|---|---|
| 可进入建筑 | VIS / COL / NAV / ANCHOR | 每扇门、每段楼梯/爬梯、破窗 |
| 掩体/围墙 | VIS / COL | 需要时加 breach/cover 锚点 |
| 猫道/吊机 | VIS / COL / NAV | 上下端 navLink |
| 撤离门 | VIS / COL / ANCHOR | extraction 触发区 |

门锚点 extras：

```json
{ "battlegameRole": "ANCHOR", "portalId": "warehouse_main",
  "clearWidth": 1.6, "clearHeight": 2.6 }
```

## 5. 验收

```bash
python tools/buildings/validate_glb.py models/buildings/v5/warehouse_a.glb \
  --target 20 8.5 14 --require VIS,COL,NAV,ANCHOR
```

必须通过：

- 尺寸误差 ≤5cm；原点在 footprint 中心地面；
- 门净宽 ≥1.3m、净高 ≥2.3m；
- 每层 NAV 有 floorId；楼梯/门有 navLink；
- COL 覆盖墙/门框/楼板/楼梯/柱；
- 室内可进、可读、有灯光/窗/掩体；
- 三角/draw call/贴图预算内。

# 建筑替换方案 v5 · 模块化预制体（Modular Prefab Kit）

> 目标：用 Blender authored 的 GLB 预制体替换运行时拼盒建筑；先保证**可读的入口/窗口/室内/楼梯/掩体**，再谈数量。  
> 关联：[玩法设计](gameplay-v5.md) · [现有资产契约](../rebuild/asset-contract.md) · [v5 建筑清单](../../data/assets/buildings.v5.catalog.json)

## 1. 为什么不继续用运行时盒子

当前 `js/world/buildings.js` 用 Box/Cone 拼建筑，解决了“有房子”的问题，但达不到可玩性要求：

- 外墙没有厚度、窗洞不真实、室内外明暗平；
- 门/窗/楼梯只是几何体，缺少“入口—掩体—视线”设计；
- 每个建筑都像同一个盒子换色，玩家记不住空间；
- 运行时无法方便地加贴图、烘焙、破损、招牌、室内道具。

v5 的建筑必须是**在 Blender 里按模块搭好、导出为 GLB 的完整预制体**。运行时只负责实例化、碰撞、导航和门/楼梯锚点。

## 2. 套件结构

### 2.1 模块（Kit Pieces）

| 类别 | 模块 | 尺寸/规则 |
|---|---|---|
| 墙 | 2m / 4m 墙段、带门洞、带窗洞、半墙、破损墙 | 高 3.0m，厚 0.24–0.3m |
| 楼板 | 4×4、4×2、楼梯井板 | 厚 0.24m，顶面为 NAV |
| 屋顶 | 平屋顶、女儿墙、坡屋顶、天窗 | 平屋顶可走；坡屋顶只做视觉 |
| 门 | 单门 1.4×2.4、双门 2.4×2.4、卷帘 4.5×4.5、破门点 | 门洞必须真实留空 |
| 窗 | 1.2×1.2、1.8×1.2、高窗/气窗 | 窗台高 0.9–1.1m，可翻越窗需明确 |
| 楼梯 | 直跑、L 型、外消防梯、爬梯 | 踏步 0.3×0.3，休息平台 ≥1.2m |
| 栏杆 | 楼梯扶手、屋顶护栏、猫道护栏 | 高 1.0–1.1m |
| 结构 | 柱、梁、雨棚、招牌、管线 | 柱 0.4×0.4m |
| 室外 | 集装箱、沙袋、混凝土路障、围墙、铁丝网 | 与地图数据配套 |

### 2.2 预制体（Prefab）

MVP 不要求运行时自由拼装。用模块在 Blender 里搭出**完整建筑预制体**，导出单个 GLB；运行时按 `key` 实例化。这样：

- 美术质量可控；
- 每栋楼有完整室内；
- 碰撞/NAV/门锚点一次做好；
- 替换时只换 GLB + 地图条目，不改运行时代码。

未来再做运行时模块拼装（同一套模块 + grammar），不阻塞 MVP。

## 3. 统一尺寸

沿用角色契约：玩家 2.0m（上限 2.2）、眼高 1.85、胶囊 0.35m。

| 项目 | 值 |
|---|---|
| 水平网格 | 2m（墙/楼板以 2m 为模数，4m 为常用跨度） |
| 层高（floor-to-floor） | 3.6m |
| 净层高 | ≥3.0m |
| 门净宽 | ≥1.4m（主门 1.6m） |
| 门净高 | ≥2.4m |
| 走廊净宽 | ≥1.8m |
| 楼梯踏步 | 0.3m 高 × 0.3m 深 |
| 楼梯净宽 | ≥1.2m |
| 窗台高 | 0.9–1.1m |
| 屋顶女儿墙 | 1.0m |
| 建筑原点 | footprint 中心、地面 y=0 |
| 旋转 | 只绕 Y 轴；导出前应用变换 |

> 旧资产契约里的 4.4m 层高是 2.5m 角色时代的遗留；v5 统一 3.6m，避免“楼层太高/太空”。

### 4.1 每栋建筑必须满足

- ≥2 个出入口（主门 + 后门/破窗/消防梯）；
- 一层有 1–2 个低掩体（桌、货架、沙袋），不做空大厅；
- 二层有 1 个可守的窗口/阳台，但窗外有掩体反制；
- 楼梯不与门正对（避免一进门就被高位打）；
- 室内至少 1 盏可见灯具 + 1 个视觉锚点（招牌/海报/货架）；
- 窗外视线长度分级：近距离（<15m）、中距离（15–40m）、长距离（>40m）；
- 所有门/窗/楼梯有 ANCHOR，NAV 连续；
- 屋顶可达时，至少有 2 条上下路径。

## 5. GLB 技术契约

### 5.1 节点

| 角色 | 命名 | 说明 |
|---|---|---|
| 可见 | `VIS__<id>` | 合并后的可见网格，按材质分组 |
| 碰撞 | `COL__<id>` | 隐藏；墙/门框/楼板/楼梯/柱/栏杆 |
| 导航 | `NAV__<id>_F0` / `_F1` | 可行走面，extras 带 `floorId` |
| 锚点 | `ANCHOR__<id>_door_main` | `portalId`、`clearWidth`、`clearHeight` |
| 锚点 | `ANCHOR__<id>_stair_0` | 上下端 floorId、navLinkId |
| 锚点 | `ANCHOR__<id>_breach_1` | 可破门/墙位置 |

节点 extras 至少：

```json
{ "battlegameRole": "COL", "assetId": "warehouse_a", "schemaVersion": 1 }
```

门锚点：

```json
{ "battlegameRole": "ANCHOR", "portalId": "warehouse_main",
  "clearWidth": 1.6, "clearHeight": 2.6 }
```

### 5.2 碰撞

- 外墙/内墙/门框/窗台/柱/栏杆：cuboid 代理（优先）或低模 trimesh；
- 楼板/楼梯/坡道：独立 COL；
- 门洞/窗洞真实留空，禁止整栋 AABB；
- 屋顶只在外侧有女儿墙 COL，内部可走；
- 碰撞代理面数 ≤ 视觉的 15%，或 ≤3k 三角/栋。

### 5.3 NAV

- 每层一个 NAV 面，extras `floorId`；
- 楼梯/外梯用显式 `navLinkId` 连接；
- 门口/窗口/破口加 link；
- 导航面不覆盖家具/货架（由 COL 阻挡）。

### 5.4 性能预算

| 类型 | 视觉三角 | 材质/ draw call | 贴图 |
|---|---|---|---|
| 小屋/哨所 | 3–6k | 2–3 | 1K |
| 住宅/商铺 | 8–15k | 3–5 | 2K |
| 公寓/行政楼 | 15–28k | 4–6 | 2K |
| 仓库/地标 | 25–45k | 5–8 | 2K trim + 1K 道具 |
| LOD1 | 视觉 40–60% | 同材质 | 同 |
| LOD2 | <500 三角 | 1 | 无 |

- 一栋建筑最多 6 个 draw call（按 trim/墙/屋顶/玻璃/金属/道具分组）。
- 贴图：一张 2K trim sheet + 一张 1K 道具/贴花图集，禁止每栋楼独立 4K。
- 纹素密度：主立面 512–1024 px/m；远景/屋顶 256–512 px/m。

## 6. Blender 流程

1. **灰盒（Blockout）**：按 2m 网格搭体块、门洞、楼板、楼梯；在游戏里跑一遍，确认门/楼梯/视线。
2. **模块化拆件**：墙、楼板、屋顶、门窗、楼梯、栏杆、柱；统一 pivot（底面中心）和 2m/4m 模数。
3. **Trim Sheet 规划**：墙裙、檐口、窗框、门框、金属边、破损边；2K 一张，全场景复用。
4. **搭预制体**：用模块拼出 14 个 prefab；每个 prefab 加室内道具（桌、货架、箱子、灯）。
5. **UV/烘焙**：非重叠 UV；AO/法线/曲率烘焙；破损/污渍用贴花/顶点色。
6. **LOD**：LOD0/1/2；LOD2 只保留轮廓。
7. **碰撞代理**：复制墙/楼板/楼梯，简化为 cuboid/低模，命名 COL。
8. **NAV/ANCHOR**：按层/门/楼梯/破口生成；extras 写入。
9. **导出 GLB**：Y-up，应用变换，根节点 scale=1，原点 footprint 中心地面。
10. **自动验证**：`python tools/buildings/validate_glb.py <glb> --target w h d`。
11. **入 Catalog**：`data/assets/buildings.v5.catalog.json` 状态改 `approved`。
12. **入 Manifest**：放到 `models/buildings/v5/`，`node tools/gen_manifest.cjs`。
13. **地图替换**：把 `pb('warehouse',...)` 改成 `b('warehouse_a',...)`，运行 QA。

> 建议先做 `warehouse_a` + `admin_b` + `house` 三栋，跑通“A 点/B 点/住宅”的完整流程，再批量生产其余。

## 7. 运行时替换

当前 `World._buildBuildings` 已支持两种条目：

```js
// 运行时程序化盒子（旧）
{ type: 'warehouse', x: 235, z: 112, ry: 0 }

// authored GLB 预制体（v5）
{ key: 'warehouse_a', x: 235, z: 112, ry: 0 }
```

替换步骤：

1. 将 `warehouse_a.glb` 放入 `models/buildings/v5/warehouse_a.glb`；
2. 运行 `node tools/gen_manifest.cjs`，manifest 会自动收录 v5 建筑；
3. 地图数据把 `type` 改为 `key`；
4. 删除对应的 `pb(...)` 条目；
5. 跑碰撞/楼梯/门/导航验收。

无需重写运行时；GLB 的 `COL__*` 会自动生成 Rapier collider，`VIS__*` 显示，`NAV__*` 给后续导航烘焙，`ANCHOR__*` 给门/楼梯。

### 7.1 程序化建筑的去留

- v5 MVP：保留 `js/world/buildings.js` 作为**灰盒/占位**和远景填充；
- 关键战斗建筑（A/B、住宅、公寓）全部换 authored prefab；
- 程序化建筑不再承担“主战斗空间”，只做背景/边界填充；
- 最终目标：删除程序化建筑，只保留 prefab + 少量道具。

## 8. 美术方向

三套主题，共用一套模块和 trim sheet 逻辑：

1. **黑港（MVP）**：海风、集装箱、锈蚀钢板、混凝土、褪色蓝/橙/绿；冷灰天空、湿地反光。
2. **边境村**：灰泥、砖、瓦顶、晾衣绳、土墙；暖黄/土红。
3. **沙漠泵站**：混凝土、沙色、管线、油罐；强日照、长阴影。

可读性规则：

- 敌人轮廓不与主色冲突：避免大面积纯红/纯蓝；
- 可交互门/梯/目标用暖色/灯光/形状编码；
- 重要通道用地面磨损/顶光/门框强化；
- 每个区域有一个独特地标（水塔、吊机、钟楼、货架编号）。

## 9. 验收清单

- [ ] bbox 与目标尺寸误差 ≤5cm；
- [ ] 原点在 footprint 中心地面；
- [ ] 门净宽/净高、楼梯净宽、层高符合契约；
- [ ] 每层 NAV 连续，楼梯/门有 link；
- [ ] COL 覆盖墙/门框/楼板/楼梯/柱/栏杆；
- [ ] 门洞/窗洞真实留空，无 invisible wall；
- [ ] 室内可进、可读、有灯光/窗/掩体；
- [ ] 屋顶可达时两条路径；
- [ ] 三角/draw call/贴图在预算内；
- [ ] 在 160m 地图里 60fps，无卡墙/AI 卡门；
- [ ] 玩家从入口到目标 ≤20 秒，不迷路。
